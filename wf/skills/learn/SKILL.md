# 📚 学新东西的顺序

**定位**：`RULES.md` 教学模式管「一轮怎么讲」，本技能管「一份资料按什么顺序啃」。
教学模式里「用户定过学习顺序 → 这块排第几」——**用户没另外定过，就按这四步排**。
**做东西也走同一个顺序**，见 `RULES.md`「工作顺序」（多了链路图、分文件、写函数几层）；本技能只管学资料。
**触发**：用户说要学 / 看懂某本书、某章、某篇文档或论文、某段别人的代码；`/wf:exec` 第 2 步引导 `📖学习点`。

## 为什么要有第 1 步

视频适合快速建直觉（「这东西大概长啥样」），书适合搭结构、查准确（「它到底怎么成立的」）。
好顺序 = **先视频建直觉 → 再看书理骨架 → 用到时回书查细节**。
这里没有视频，**我来顶视频那一格**：他翻开书之前，先给他一个能「看见」的直觉。

## 四步

### ① 直觉（我顶「视频」）
- 只回答「这东西大概长啥样」：一个生活类比，或一张 3～4 行的小数字表，**不上公式、不上新符号**。
- 长度一屏以内，相当于视频的前一分钟；讲不进一屏 = 我在讲书，不是在给直觉。
- 结尾不总结，直接接 ②：「你翻一下目录/简介，猜这一章想解决什么问题？」

### ② 看之前：先立一个问题
- **问题由他说**，我不代答（同教学模式「答案必须他亲口说出来」）。
- 说不出来 → 只把目录或简介里最相关的一行指给他，再问一次，不给答案。
- 立住的问题记一行 `❓本章问题：<他的原话>`，④ 要拿它对账。

### ③ 看的过程中：只抓骨架
- 他卡在某个推导 → **标记、跳过**，不当场讲透。记 `🔖跳过：<位置> <卡在哪>`。
- 目标是先过完整体思路；很多前面的坑，看到后面自然就懂了。
- 他主动要讲某个点 → 按教学模式一小块一小块来；没要求就别展开。

### ④ 看完后：合上，自己讲一遍（最关键）
- 让他用三句话复述：**解决什么问题 / 核心思路 / 局限在哪**。
- 对照 `❓本章问题`：答上了没有？
- **讲不出来的那句，就是要回去重看的地方**——只回看那里，加上 ③ 里还没自己解开的 `🔖跳过`。回看照样走 ②→④，不从头重读。
- 三句都讲得出 → 这块收工，往下一章 / 下一个学习点走，不补「完整版」。

## 记在哪

- 在流水线里（有代码根、有 `📖学习点`）→ `❓` `🔖` 和 ④ 的三句复述记到 `tasks/<模块>.md` 该学习点下面，下轮会话接着用。
- 一次性学习（没进流水线）→ 只在对话里过，不建文件。

## 禁止

- 跳过 ① 直接让他啃原文 / 原代码（就是教学模式「别让他从压缩包里读原文」）。
- ③ 里把每个跳过的推导都补讲一遍——那等于把 ③ 变回逐页精读。
- ④ 由我替他讲三句话，或他没讲完我就给「标准答案」。
