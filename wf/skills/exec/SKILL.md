# ④ 执行

**验收**：`pytest` / `mypy` / `ruff check` 三项**实际跑过并贴出输出**，全绿；全部模块做完时，「零」的真样本端到端跑通。

## 主 + 子 agent 机制

1. **主会话 = 进度跟踪器**：读 `tasks/progress.md`，挑出未完成且**相互独立**的模块。
2. **派 agent 前先清「学习点」**：`tasks/<模块>.md` 标了 `📖学习点` 的，主会话按 `/wf:learn` 四步（我先给直觉 → 他立问题 → 抓骨架 → 合上讲三句）先引导用户——问机制、拆小、不给答案。引导完（用户能说出该怎么做）再派 agent 实现。
   ⚠️ 学习点是少数，**不是每模块都讨论**（8/26 已定：执行阶段维持并行）。没标学习点的模块直接进第 3 步。
3. **并行派生子 agent**：每个独立模块一个 general-purpose 子 agent（工具全开），按**中档**运行。喂给它 `design.md` 的链路图 +「样本走一遍」+ 对应模块章节 + `tasks/<模块>.md`。
4. **子 agent**：`cd` 到代码根 → 按 ②design 落好的骨架**填空**（签名已定死，不改签名；要改回 ②），先写朴素版 → 写 pytest（第一条用「样本走一遍」里本模块的进出数据）→ **实际运行**三件套 → 把命令输出报回主会话。
5. **主会话**更新 `progress.md` 和 `tasks/<模块>.md`，循环下一批。
6. **并行前提是真解耦**：多个模块要改同一个共享文件，那部分**先串行做掉**再并行其余，避免撞车。
7. **全部模块跑绿后，拿「零」的真样本端到端跑一遍全链**，输出贴出来对照期望输出——这是「写函数」层的出口。跑不通按下面「调试」定位。

## 代码门禁

- 核心逻辑必须有 pytest；硬件 / IO / ROS2 接口层用 mock，难单测的标「需硬件验证」。
- 完成后**必须实际运行** `pytest`、`mypy`、`ruff check` 并贴输出。未通过不算完成；跑不了要说明原因，**不得谎称通过**。

## 范围（读和改都按需，不全量）

- **只读当前任务相关的文件**，不要一上来全量扫整个代码库。
- 只改当前任务相关模块，不顺手改无关代码，不过度设计。
- **细节用到时再查**：⓪ 只查到接口级，具体 API 用法由子 agent 写到那里时当场查官方文档，来源要求同 `/wf:research`，不凭印象写。
- 文档冲突以 `design.md` 为设计权威；影响当前任务时停下确认。

## 调试

定位按 `RULES.md`「工作顺序」的调试那条：先复现、拿到出错的那条数据，在链路图上逐个箭头查，找到第一个不对的箭头再下到模块。查出是链路图本身错了 → 回 ②design 改图，不在代码里打补丁。

档位默认**中**；lint / typo 级降**低**；并发 / 跨多文件难 bug 升**高**（低档啃不动硬 bug）。

## 收尾

模块跑绿 → 按 `RULES.md` 调度行报「模块 X 已就绪，可提交」→ 走 `/wf:wrap`。
