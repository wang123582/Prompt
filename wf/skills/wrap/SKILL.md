# 收尾（每完成一个任务必做）

四步按顺序走完，一步都不许跳。

## 1. 多余物检测

范围**只限本次任务碰过的文件和目录**，不全量扫仓库。逐项列候选：

- **调试残留**：临时脚本、临时目录、调试打印、注释掉的死代码
- **临时产物**：`*.tmp` / `*.bak` / `*.orig`、备份副本、测试留下的中间文件
- **失效代码**：本次改动后无人引用的函数 / 类 / 文件、不再需要的 import 与依赖
- **重复实现**：本次新增的和已有模块功能重叠的部分
- **文档漂移**：`design.md` / `USAGE.md` / `tasks/` 里已和实现对不上的条目

**只报告，不擅自删。** 每条写明判定依据，等用户点头再动手；删完在「最近变更」记一条。
一个候选都没有 → 明确说「本次无多余物」，不许沉默跳过。

## 2. 更新文档

- `tasks/progress.md` 勾进度（可标 `⚠️ blocked`）
- `tasks/<模块>.md` 勾已完成子任务
- `CONTEXT.md`「最近变更」加一条：日期 + 内容 + 关键决策 / 假设
- 改了影响运行 / 构建 / 参数的代码 → 同步更新 `USAGE.md` 对应小节

## 3. 写下一轮「当前任务」

写进 `CONTEXT.md`，**必须含 `验收标准` 和 `建议档位` 两个字段**。
下一阶段该不该 `/clear`、该切哪档，**在下一轮回复的调度行里说**，不在这里重复一遍。

## 4. Git

有模块测试通过但未提交 → 按调度行报「模块 X 已就绪，可提交」。
**等用户说「可以」再 commit。** commit 信息含模块名 + 测试结果，末尾加
`Co-Authored-By: Claude <noreply@anthropic.com>`
