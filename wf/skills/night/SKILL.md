# 🌙 夜间模式

**只有用户手动 `/wf:night` 才能进入，我不能自行开启。**
**进入后本技能压过 `RULES.md` 和其它技能里一切「问用户 / 等他点头 / 等他亲口讲」的规定**——冲突时以本技能为准。

## 目标：做完才收工

- 目标 = 用户这次 `/wf:night` 给的参数；没给参数 = `tasks/` 里未完成的任务。
- **完成 = 目标的验收标准真过了**。例：「完成代码」= 代码写完 + `pytest` / `mypy` / `ruff check` 实跑全绿，不是写了一半留个 TODO。
- 中途不提问，最后一条回复也不许以问句收尾。
- 遇歧义：用**最稳妥假设**继续，假设写进夜间日志和 `CONTEXT.md`「待确认问题」，早上由用户裁决。

## 被覆盖的白天规定

- **教学模式 / 📖学习点**：不引导，记进日志「早上待复核」。
- **工作顺序各层出口「他讲得出来」**：我自查后往下走，同样记进待复核。
- **链路图闸门**：我自己画图，写 `链路图确认：<日期> 夜间自定，待早上复核`，闸门放行。早上他不认，就按 `RULES.md`「回退」回到那一层改。
- **动手闸 / 三层问**：不报、不问，直接做。
- **停点**：命中 = 换路线继续，不是停手。同一子任务**换过 3 条路线**还不通才标 `⚠️ blocked`，转去做下一个。

## 仍然不破的红线

- **代码根目录没拿到用户明确指定就不许写**：标 `⚠️ blocked`，绝不猜一个路径硬写。
- **不提交 git**：只在 `tasks/progress.md`「待提交 Git」区块累积清单。
- 理由：两条都不可逆。用户没明确说要破，就按保留算。
- 收到「wf 额度守卫」提醒 → 照它说的收尾、后台 sleep，醒来接着干；不许硬撑到额度撞墙。

## 夜间日志（最重要）

写在代码根 `tasks/night-<YYYY-MM-DD>.md`。**每做完或每卡住一个子任务就立刻追加一条**，不攒到最后——半夜中断了，日志也还在。

每条按这五项写：

```
### <时间> <子任务>
- 做了什么：
- 遇到什么困难：<原始报错 / 现象，贴原文，不转述>
- 怎么改的：<改了哪个文件的哪段>
- 为什么这么改：<思路；试过、放弃了哪条路，为什么放弃>
- 结果：<验证命令 + 输出摘要；没验证就写「未验证」>
```

**如实**：
- 失败就写失败，绕过去就写绕过去，没跑的测试不写成「通过」。
- 一个问题来回试了几次，每次都记，不只记最后成功的那次——早上要看的正是思路怎么走过来的。
- 夜里做的假设、自定的链路图、跳过的学习点，全部列进日志末尾「早上待复核」。

## 收尾

- 日志顶部补一段**当晚汇总**：目标完成没有 / 做了哪几件 / 哪些 `blocked` 及原因 / 待复核清单 / 待提交清单。
- `CONTEXT.md`「最近变更」只记一行，指向这份日志；照常走 `/wf:wrap` 第 2、3 步。
